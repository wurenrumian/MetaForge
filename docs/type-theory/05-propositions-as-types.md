# 05 · 命题即类型

> **一句话**：逻辑里的每个连接词都对应一个数据类型，每条推理规则都对应一种程序构造；所谓“证明命题 A”，就是写出一个类型为 `A` 的程序。

## 一个返回值引发的困惑

先看一段几乎每本工程书都会出现的 Go 代码：

```go
func ParsePort(s string) (int, error)
```

它的类型告诉你：调用之后你会同时拿到一个 `int` 和一个 `error`。可它在语义上想说的是“要么拿到端口号，要么拿到错误”。返回值是一个**乘积**，需求却是一个**和**。这个错位立刻产生了后果——调用方可以这样写：

```go
port, _ := ParsePort(s)   // 忽略 error，port 此时是 0
```

编译器不会拦你。因为从类型上看，你确实得到了一个 `int`；它不知道这个 `int` 只有在 `error` 为 `nil` 时才有意义。于是“检查返回值”这件事只能靠代码评审、lint 规则和人的自觉。

同样的问题有很多变体：用 `int` 表示“索引可能不存在”，用 `bool` 加 `out` 参数表示“可能失败”，用 `void*` 表示“某种东西”。这些做法的共同点是：**类型里没有“或”，也没有“假”**。没有它们，你没法说“这里要么是 A 要么是 B”，也没法说“这个分支永远不会发生”。

Curry–Howard 对应（Curry–Howard correspondence）说的正是：这些逻辑连接词本来就可以是类型。不是“类比成类型”，而是**在 Agda 里它们就是类型**。

## 一张完整的对应表

第 01 篇给过一张表，这里把它补全，并加上“证明长什么样”这一列：

| 逻辑 | 读法 | 类型 | 证明的形状 |
| --- | --- | --- | --- |
| `A` 成立 | 命题 | 类型 `A` | 一个类型为 `A` 的项 |
| `A → B` | 蕴含 | 函数类型 `A → B` | 一个函数，输入 `A` 的证明，输出 `B` 的证明 |
| `A ∧ B` | 且 | 有序对 `A × B` | 一对证明 `(a , b)` |
| `A ∨ B` | 或 | 和类型 `A ⊎ B` | 一个带标签的值：`inj₁ a` 或 `inj₂ b` |
| `⊤` | 真 | 单元类型 | `tt` |
| `⊥` | 假 | 空类型 | 没有 |
| `¬ A` | 非 | `A → ⊥` | 一个把 `A` 的证明变成矛盾的函数 |
| `∀ x. P x` | 全称 | 依赖函数类型 `(x : A) → P x` | 对每个 `x` 都给出一份证明 |
| `∃ x. P x` | 存在 | 依赖对类型 `Σ A P` | 一个具体的 `x` 加上 `P x` 的证明 |

最后两行属于依赖类型的范围（第 04 篇），本章只用到前七行。这张表的读法有三个层次，缺一个都会让人卡住：

1. **命题 = 类型**：一个问题就是一个类型。
2. **证明 = 项**：回答这个问题，就是构造出该类型的一个元素。
3. **检查证明 = 类型检查**：Agda 不判断“这句话对不对”，它只判断“这个项是不是这个类型的”。

第三层是关键。逻辑学里“证明”是一个社会性概念，需要同行评议；而在这里，它是一个可以被机器在毫秒级验证的语法对象。代价是：能被机器验证的命题，必须用一套非常朴素的规则写出来。

## 把连接词定义出来

下面是本章要用的全部定义。它们和标准库里的写法几乎一致，但这里不依赖任何 `open import`，你可以整段粘进一个空文件。

```agda
module Chapter05 where

infix 3 ¬_
infixr 2 _×_
infixr 4 _,_
infixr 1 _⊎_

data ⊤ : Set where
  tt : ⊤

data ⊥ : Set where

data _×_ (A B : Set) : Set where
  _,_ : A → B → A × B

data _⊎_ (A B : Set) : Set where
  inj₁ : A → A ⊎ B
  inj₂ : B → A ⊎ B

¬_ : Set → Set
¬ A = A → ⊥
```

逐条解释，重点不是语法，而是“这条定义对应哪条推理规则”。

### `⊤`：为真，因为恰好有一个证据

`⊤`（读作“top”）只有一个构造子 `tt`。所以“证明 `⊤`”这件事没有信息量：永远只有一种做法。逻辑上，`⊤` 是那个恒真的命题——你不需要任何前提就能断言它。

反过来说，如果某个类型有且仅有一个元素，那么“证明它”就不携带任何信息，这正是“真”的行为。

### `⊥`：为假，因为没有证据

```agda
data ⊥ : Set where
```

这是一条合法的定义：一个**没有构造子**的数据类型。它没有任何元素，所以永远无法构造出 `⊥` 的值。这就是“假”。

注意一个容易滑过去的点：`⊥` 的类型是 `Set`，它和其他类型平起平坐。它不是一个特殊的报错状态，就是一个空集合。

### `×`：证明“且”，就是同时给出两个证明

`_×_` 只有一个构造子 `_,_`，它接收一个 `A` 和一个 `B`，返回 `A × B`。所以：

> 要证明 `A ∧ B`，给出 `a : A` 和 `b : B`，写成 `a , b`。

消去方向也在模式匹配里：当你的函数收到一个 `A × B`，你可以用 `(a , b)` 把它拆成两半。这就是“且消去”。

### `⊎`：证明“或”，必须说明是哪一边

`_⊎_` 有两个构造子：`inj₁`（injection 1，左注入）接收 `A`，`inj₂` 接收 `B`。

这是本章最重要的一个设计。`A ⊎ B` 的一个元素不是“某个东西，可能是 A 也可能是 B”，而是**明确带着标签的**：`inj₁ a` 告诉你“这一边是 A，而且这就是那个 a”。要使用它，你必须分别处理两种情况：

```agda
-- 假设我们有一个把 A 和 B 都变成 C 的办法
⊎-elim : {A B C : Set} → (A → C) → (B → C) → A ⊎ B → C
⊎-elim f g (inj₁ a) = f a
⊎-elim f g (inj₂ b) = g b
```

这个函数就是逻辑里的“或消去”：如果你能从 A 推出 C，也能从 B 推出 C，那么从“A 或 B”就能推出 C。代码上它只是两行模式匹配。

### `¬`：否定不是“假”，是“会推出矛盾”

```agda
¬_ : Set → Set
¬ A = A → ⊥
```

这是本章第二个关键设计。`¬ A` 不是一个新的原始概念，它被**定义**成 `A → ⊥`：给我一个 A 的证明，我就能造出矛盾。

所以“证明 `¬ A`”意味着：假设 `A` 成立，我能推出不可能的事。用工程语言说，否定是一个**反驳过程**，不是一个布尔标志。

## 五个证明，五种程序

下面五个证明都很短，但每一个都对应一条你在逻辑课上背过的规则。看代码时请问自己：“这段程序在做什么计算？”——答案通常就是这条规则的直观含义。

```agda
-- 同一律：A → A
identity : {A : Set} → A → A
identity x = x

-- 且交换：A ∧ B → B ∧ A
∧-comm : {A B : Set} → A × B → B × A
∧-comm (a , b) = b , a

-- 或交换：A ∨ B → B ∨ A
∨-comm : {A B : Set} → A ⊎ B → B ⊎ A
∨-comm (inj₁ a) = inj₂ a
∨-comm (inj₂ b) = inj₁ b

-- 蕴含传递（三段论）：(A → B) → (B → C) → A → C
→-trans : {A B C : Set} → (A → B) → (B → C) → A → C
→-trans f g a = g (f a)

-- 爆炸原理：从假能推出任何命题
⊥-elim : {A : Set} → ⊥ → A
⊥-elim ()
```

**`identity`** 是恒等函数。逻辑上它说“如果 A 成立，那么 A 成立”。它无聊到不值得写，但它是整个系统能运转的基础：函数应用 `f a` 就是“肯定前件”（modus ponens）。

**`∧-comm`** 只有一行，因为 `A × B` 只有一个构造子，模式匹配一次就拆完了。这里没有分支，也没有 `if`：交换两个分量是**无条件**的。

**`∨-comm`** 必须写两个分支。因为 `A ⊎ B` 的证据有两种形态，你必须分别为它们给出 `B ⊎ A` 的证据。注意返回值的标签必须反过来：拿到 `inj₁ a`（左边）就要返回 `inj₂ a`（右边）。这个“标签翻转”就是“或”的交换律的全部内容。

**`→-trans`** 里，`a` 是唯一一个非函数参数。它的实现 `g (f a)` 就是“先 A 后 B 再 C”的管道。逻辑上它对应假言三段论：如果 A 蕴含 B、B 蕴含 C，那么 A 蕴含 C。写代码时你天天在做这件事，只是从不叫它定理。

**`⊥-elim`** 是唯一需要用 `()` 的。`()` 叫**荒谬模式**（absurd pattern），意思是“这里不可能有值，所以不必给返回值”。Agda 接受它的条件很严格：只有当它从类型上看得出这个位置不可能有构造子（这里是空类型 `⊥`）时才允许。逻辑上这就是“爆炸原理”（ex falso quodlibet）：从矛盾能推出任何东西。

工程上它的意义常被误解。它不是“错误处理”，而是“**这个分支不存在**”。比如你在解析一个只可能是 `Left` 或 `Right` 的联合类型，如果前面的检查已经排除了 `Left`，剩下的分支里你拿到的不该是“可能为空的 Left”，而是“一个不可能被构造的值”。`⊥-elim` 让你在不写 `throw`、不写 `return default` 的情况下把这条路封死。

## 否定：能进不能出的那道门

一个从 A 到“A 不假”的证明：

```agda
¬¬-intro : {A : Set} → A → ¬ ¬ A
¬¬-intro a = λ f → f a
```

展开定义看：`¬ ¬ A` 就是 `(A → ⊥) → ⊥`。所以 `¬¬-intro` 收到 `a : A`，返回一个函数；这个函数收到 `f : A → ⊥`，就把 `a` 喂给 `f` 得到矛盾。这就是标准的“引入双重否定”。

反过来呢？`¬ ¬ A → A` 在 Agda 里写不出来。这不是你不够聪明，而是它**在直觉主义逻辑里不成立**。

原因值得慢慢说。`¬ ¬ A` 的证明是一个函数：**如果**有人给你 `A → ⊥`，你就能造出矛盾。它是一张“反驳反驳”的许可证。但要从它变出一个 `A`，你必须真的拿出一个 `A`——而这张许可证只在你**已经假设了 ¬A** 的时候才启动。它没有告诉你 A 长什么样，甚至没有告诉你 A 是可以被构造的。

<div class="human-note">
<strong>一个不严谨但有用的类比：</strong>`¬ ¬ A` 像一份“本餐厅今天不可能没位子”的保证书。它确实排除了“没位子”这种可能，但它没给你桌号、没给你时间，也没给你一张能坐下的桌子。要坐下，你需要的是位子本身，不是“不可能没位子”的证明。
</div>

用工程语言说：`¬ ¬ A` 是一个**延续**（continuation）——它接受一个“A 失败时的处理函数”。这类东西在需要“控制流反向传递”的场合很有用（CPS 变换、`Either` 的错误通道），但它不直接产出值。

所以有一件事你必须接受：在直觉主义逻辑里，“不能证明 A 不假”和“A 成立”是两件不同的事。把它们当成同一件事，等价于假设**每个问题都能被判定**——这就是排中律（law of excluded middle）：

```agda
-- 这只是声明，不是证明：把它当公理加进来，就进入经典逻辑
postulate
  excluded-middle : {A : Set} → A ⊎ ¬ A
```

Agda 允许 `postulate`，但那意味着你不再是在一个“所有东西都能计算”的系统里工作了。加上这条公理后，`¬ ¬ A → A` 就能证出来（留作练习）。本站后面的章节都只在直觉主义范围内活动，不加这条公理。

顺带说一个好的对照：三重否定是可以消掉的。

```agda
¬¬¬-elim : {A : Set} → ¬ ¬ ¬ A → ¬ A
¬¬¬-elim h a = h (λ k → k a)
```

读法：`h` 是一个“反驳 ¬¬A”的东西；给它一个 `¬¬A`（也就是 `(A → ⊥) → ⊥`），它就吐出矛盾。而我们有 `a : A`，所以 `λ k → k a` 正是一个 `¬¬A`。于是把 `h` 应用上去就得到了 `⊥`，也就是 `¬ A`。这条规律在经典逻辑里也成立，直觉主义只是**恰好**也保住了它——它不需要排中律。

## 柯里化在逻辑上是什么

```agda
curry : {A B C : Set} → (A × B → C) → A → B → C
curry f a b = f (a , b)

uncurry : {A B C : Set} → (A → B → C) → A × B → C
uncurry f (a , b) = f a b
```

这两个函数在 Haskell 里天天出现，通常被解释成“把多元函数改成一元函数”。放到逻辑里，它们说的是：

> `(A ∧ B) → C` 与 `A → (B → C)` 是**等价的**。

也就是“如果你有一个 A 和一个 B 就能得到 C” ⇔ “如果你有一个 A，那么只要再给一个 B 就能得到 C”。这两句话在自然语言里几乎无法区分，而类型系统把它们的差别精确化了：左边一次拿到两个前提，右边分两次拿到。`curry` 和 `uncurry` 就是这两个方向。

Agda 里所有函数本质上都是一元的：`A → B → C` 只是 `A → (B → C)` 的语法糖（`→` 右结合）。所以“多元函数”其实一直是柯里化形式，`uncurry` 才需要显式地把参数打包成对。

有意思的是，这条等价在工程上也有直接后果：一个接收配置结构体的函数，和一个接收配置各字段的柯里化函数，在类型上是可以互相转换的。选哪个，取决于哪个让调用点更好读——而不是哪个“更正确”。

## 构造证明和写程序是同一件事

到这里，Curry–Howard 应该已经不像一句口号了。我们把它落到编辑器的操作上：

假设你在 Agda 里写下目标：

```agda
∨-comm′ : {A B : Set} → A ⊎ B → B ⊎ A
∨-comm′ x = ?
```

goal 是 `B ⊎ A`，context 里有 `x : A ⊎ B`。这时你能做的动作只有两种：

1. 对 `x` 做模式匹配（`C-c C-c`），把它拆成 `inj₁ a` 和 `inj₂ b` 两种情形；
2. 对 goal 挑一个构造子（`C-c C-r`）：`inj₁` 还是 `inj₂`？

这两个动作，一个对应“或消去”，一个对应“或引入”。你在编辑器里按键的顺序，就是一条自然演绎证明的书写顺序。**Agda 的交互式证明不是在“帮助你写证明”，它是在强迫你把证明写成一棵树，而每个节点都是一个构造子选择。**

再看 `inj₁` 这个构造子本身。它接收 `a : A` 返回 `A ⊎ B`。翻译成逻辑：**要证明“A 或 B”，只需要证明 A**。`inj₁ a` 就是“我选左边”这个动作的具体化——而且这个选择被记录在值里，后面谁用这个证明，都能看见你选了哪边。

这就是为什么 `⊎` 比 C 的 `union` 强得多。C 的 `union` 不知道当前活着的是哪个成员，你必须自己维护一个 tag；Agda 的 `⊎` 把 tag 和值绑在一起，并且**类型检查器会强制每个使用者处理全部 tag**。漏掉一个分支，编译器就报错。C 里漏掉一个 `switch` 分支，编译器只会默默往下走。

::: tip 一个立刻能用的检查习惯
下次写“返回错误码 + 输出参数”的接口时，问一句：这个函数的返回值语义上是乘积还是和？如果是和，那就是一个 sum type 的位置。语言不支持 sum type 时，用带 tag 的结构体也比裸 `int` 强——至少使用者必须显式取出 tag。
:::

## 人话总结

<div class="human-note">
<strong>如果只记住一件事：</strong>逻辑连接词和数据类型是同一批东西：`∧` 是有序对，`∨` 是带标签的和，`→` 是函数，`⊥` 是空类型，`¬A` 是“从 A 到空的函数”。因此“证明一个命题”和“写一个该类型的程序”不是两件事——它们是同一件事的两种说法，而 Agda 只认后一种说法。
</div>

## 常见误解

**误解一：命题即类型只是一个好听的类比。**

不是类比。在 Agda 里没有单独的“命题”语法：`A ⊎ B` 既是可以被模式匹配的数据类型，也是可以被证明的命题。你没法说“这个 `⊎` 是数据，那个 `⊎` 是逻辑”——它们是同一个定义，取决于你怎么用。

**误解二：`A ⊎ B` 就是逻辑里的“A 或 B”，两者完全一样。**

只在经典逻辑里一样。直觉主义的 `⊎` 携带“是哪一边”的证据，因此 `A ⊎ ¬ A`（排中律）证不出来。这不是缺陷：它换来的是每个证明都能被当作程序执行，而且执行结果里真的包含分支信息。代价是你不能对不可判定的命题做“要么……要么……”的推理。

**误解三：既然类型检查通过，程序就一定对。**

类型检查保证的是“这个项属于这个类型”。如果类型写错了——比如你把“端口在 1–65535 之间”写成了 `Int`——那么检查通过也毫无意义。Curry–Howard 保证的是**证明与命题的一致性**，不是**命题与需求的一致性**。规格仍然要人来写，而人会把规格写错。

**误解四：证明写出来了，就应该拿去跑。**

Agda 的证明项确实可以被求值，但它的计算内容通常不是你想要的那个算法。一个用归纳法证出的排序正确性，求值时可能展开成指数级的项。实践中，Agda 用 `@0`（运行时不保留的参数）和 `opaque` 之类的机制把证明擦除，只留下数据。**证明用来让你相信，不一定要用来执行。**

## 本章小结

- `⊤`、`⊥`、`×`、`⊎`、`→`、`¬` 六个定义，完整覆盖了命题逻辑的连接词。
- 构造子是“引入规则”，模式匹配是“消去规则”；写证明就是在选构造子、拆构造子。
- `⊎` 携带标签，所以“或”的两个分支都必须处理，这就是穷尽性检查的来源。
- `A → ¬ ¬ A` 可证，`¬ ¬ A → A` 不可证；后者等价于排中律，属于经典逻辑。
- 柯里化对应 `(A ∧ B) → C` 与 `A → (B → C)` 的等价，工程上的“参数打包”和逻辑上的“前提分组”是同一件事。

## 练习

1. 证明分配律：`A × (B ⊎ C) → (A × B) ⊎ (A × C)`。提示：先拆 `A × (B ⊎ C)`，再对第二个分量分两种情况；两种情况返回的标签不同。
2. 证明逆否命题：`(A → B) → (¬ B → ¬ A)`。然后解释为什么反方向 `(¬ B → ¬ A) → (A → B)` 在直觉主义里证不出来（它同样等价于排中律的一个形式）。
3. `∧-comm` 只写了一行，`∨-comm` 写了两行。用“构造子个数”解释这个差异，并预测 `⊤ → ⊤` 的证明需要几行。
4. 在 `postulate excluded-middle` 存在的前提下，写出 `¬ ¬ A → A` 的证明。提示：对 `excluded-middle {A}` 做模式匹配，`inj₂` 分支里你手上是 `¬ A`，而目标里有一个 `¬ ¬ A`——把两者撞在一起。
