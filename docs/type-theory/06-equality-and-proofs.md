# 06 · 等式与证明

> **一句话**：`≡` 是一个归纳定义的数据类型，`refl` 是它唯一的构造子；能写下 `refl` 当且仅当两边在**定义上**相等，其余的相等都要靠归纳和重写一步步搭出来。

## 为什么有的等式一行就够，有的要写四行

在 Agda 里试这两件事，结果会让你意外：

```agda
+-identityˡ : (n : ℕ) → zero + n ≡ n
+-identityˡ n = refl          -- 通过
```

```agda
+-identityʳ : (n : ℕ) → n + zero ≡ n
+-identityʳ n = refl          -- 报错：n + zero != n
```

加法是交换的，这两个命题在数学上等价。可一个 `refl` 就过，另一个的 `refl` 直接报错。报错信息里那句 `n + zero != n` 尤其让人困惑：这两个东西明明相等啊。

答案是：Agda 说的“相等”有两种，而 `refl` 只认第一种。

- **定义相等**（definitional equality，也叫判断相等 judgmental equality）：两边的项经过计算（归约）之后变成同一个东西。
- **命题相等**（propositional equality）：两边不一定是同一个项，但你有一个 `≡` 类型的证据说它们相等。

`zero + n` 归约成 `n`，所以两边是同一个项，`refl` 直接可用。`n + zero` 在 `n` 未知的时候**卡住了**（stuck）：`_+_` 是按第一个参数做模式匹配的，`n` 既不是 `zero` 也不是 `suc _`，所以一条规则都用不上。它不是“等于 n”，它是“暂时什么都不是”。

这就引出了本章的主线：证明等式的过程，就是让两边在某个具体形态下归约成同一个项。形态未知时，你必须分情况讨论，也就是做归纳。

## 同一性类型的定义

```agda
module Chapter06 where

data ℕ : Set where
  zero : ℕ
  suc  : ℕ → ℕ

_+_ : ℕ → ℕ → ℕ
zero  + m = m
suc n + m = suc (n + m)

infixl 6 _+_

data _≡_ {A : Set} (x : A) : A → Set where
  refl : x ≡ x

infix 4 _≡_
```

（`ℕ` 和 `_+_` 在第 03 篇定义过，这里重复一次以便本文件自包含。）

`_≡_` 的定义值得逐字读三遍：

```agda
data _≡_ {A : Set} (x : A) : A → Set where
  refl : x ≡ x
```

- 第一个参数 `{A : Set}` 是隐式的：类型由上下文推断。
- 第二个参数 `(x : A)` 是**显式但固定**的：一旦你写下 `x ≡ _`，左边就定死了。
- 剩下的 `: A → Set` 说明右边是另一个待填的值，所以 `x ≡ y` 是一个类型，不是一个布尔值。
- 唯一的构造子 `refl` 的类型是 `x ≡ x`：左边和右边是同一个 `x`。

于是语义变得干脆：

> `refl` 是唯一能构造 `≡` 的东西，而它只能构造“左边和右边是同一个项”的等式。

那它怎么能表达 `2 + 2 ≡ 4` 呢？因为 `2 + 2` 归约成 `4`，归约之后两边是同一个项，`refl` 就适用了。它表达的是“算出来是同一个”，不是“相信它们相等”。

这也是为什么 `≡` 只有一个构造子却不显得贫乏：它的表达力来自类型检查器先替你算了一遍。所有定义相等的等式都能用 `refl` 证明；所有不能用 `refl` 的等式，都需要你把未知量拆成已知形态。

::: warning `=` 和 `≡` 不是一个东西
Agda 里的 `_=_` 用于**定义**，比如 `double n = n + n`，它是语法层面的绑定，不是一个命题。而 `_≡_` 是本章定义的类型。看到 `=` 不要读成“相等”，读成“定义为”。
:::

## 四条基本工具

有了 `≡`，下一步是给它配上“可以怎么用”。四个函数就够撑起绝大多数证明：

```agda
sym : {A : Set} {x y : A} → x ≡ y → y ≡ x
sym refl = refl

trans : {A : Set} {x y z : A} → x ≡ y → y ≡ z → x ≡ z
trans refl q = q

cong : {A B : Set} (f : A → B) {x y : A} → x ≡ y → f x ≡ f y
cong f refl = refl

subst : {A : Set} (P : A → Set) {x y : A} → x ≡ y → P x → P y
subst P refl p = p
```

这四个定义的模式完全一样：对等式做模式匹配，`refl` 分支里两边自动变成同一个项，目标也就自动成立。这是理解整个等式证明的钥匙——没有“代数变形”，只有“把未知情况拆到已知情况”。

逐条说含义：

- `sym`：对称性。等式可以反过来用。实现是 `sym refl = refl`：当 `x ≡ y` 的证据是 `refl` 时，`x` 和 `y` 是同一个项，所以 `y ≡ x` 也是 `refl`。
- `trans`：传递性。两个等式可以接起来。`trans refl q = q`：第一个等式是 `refl` 意味着 `x` 和 `y` 是同一个项，于是要证的 `x ≡ z` 就是 `y ≡ z`，正好是 `q`。这里返回的是 `q` 本身而不是 `refl`，因为 `q` 不一定也是 `refl`。
- `cong`：同余性。如果 `x ≡ y`，那么把同一个函数作用在两边，结果仍然相等。这是“在等式两边套同一个操作”这条中学规则的形式化。
- `subst`：替换，也叫搬运。如果 `x ≡ y`，而某个性质 `P` 对 `x` 成立，那么它对 `y` 也成立。这条是四者里唯一涉及依赖类型的，下一节单独讲。

`cong` 只能处理一元函数。二元的情况（比如 `x ≡ y` 推出 `x + z ≡ y + z`）要用 `cong₂` 或者写成 `cong (λ w → w + z)`。后者更好记：把“缺一个参数”写成 lambda，二元问题就降成了一元问题。

## 归纳：把未知拆成已知

现在回到 `n + zero ≡ n`。目标里有一个未知的 `n`，而 `ℕ` 只有两个构造子，所以只有两种可能：

```agda
+-identityʳ : (n : ℕ) → n + zero ≡ n
+-identityʳ zero    = refl
+-identityʳ (suc n) = cong suc (+-identityʳ n)
```

逐行读：

第一行 `+-identityʳ zero = refl` 处理 `n = zero` 的情形。目标变成 `zero + zero ≡ zero`。`zero + zero` 匹配 `_+_` 的第一条规则，归约成 `zero`。于是两边都是 `zero`，`refl` 搞定。这就是**基础情形**（base case）。

第二行 `+-identityʳ (suc n) = cong suc (+-identityʳ n)` 证的是后继情形。目标变成 `suc n + zero ≡ suc n`。现在归约开始工作：`suc n + zero` 匹配第二条规则，变成 `suc (n + zero)`。需要证明的等式于是成了：

```text
suc (n + zero) ≡ suc n
```

`cong suc` 把两边的 `suc` 剥掉，剩下 `n + zero ≡ n`——这正好是递归调用 `+-identityʳ n` 的类型。这就是**归纳假设**（induction hypothesis），而在 Agda 里它就是一个普通的递归调用。

<div class="human-note">
<strong>一句话理解归纳法：</strong>你不是在“假设 n 时成立，证明 n+1 时成立”，你是在写一个函数——它对自己小一号的输入调用自己。Agda 的终止检查器确认这个递归真的在变小（从 `suc n` 到 `n`），于是接受这个定义。数学归纳法和结构递归在这里是同一件事。
</div>

还有一个容易被忽略的细节：为什么是 `cong suc` 而不是别的？因为归约后目标左边多了一层 `suc`，你要在两边同时套上同一个函数把这个外壳对齐。**每当目标两边形状不同，就问自己：它们在定义上差了什么外壳？** 差一层 `suc` 就用 `cong suc`，差一个参数就用 `cong (λ w → ... w ...)`。

## 结合律几乎白送，交换律要付利息

结合律的证明和上面几乎一样：

```agda
+-assoc : (a b c : ℕ) → (a + b) + c ≡ a + (b + c)
+-assoc zero    b c = refl
+-assoc (suc a) b c = cong suc (+-assoc a b c)
```

`a = zero` 时：`(zero + b) + c` 归约成 `b + c`，右边 `zero + (b + c)` 也归约成 `b + c`，两边同一个项，`refl`。`a = suc a` 时：左边归约成 `suc ((a + b) + c)`，右边归约成 `suc (a + (b + c))`，剥掉 `suc` 就是归纳假设。

为什么它这么轻松？因为 `_+_` 递归在**第一个**参数上，而结合律要动的恰好也是第一个参数。两者方向一致，证明就是“跟着定义走”。

交换律不一样，它要把第一个参数挪到第二个位置上去。这就必须先把“加法在第二个参数上也能推进一步”这件事单独证出来：

```agda
+-suc : (n m : ℕ) → n + suc m ≡ suc (n + m)
+-suc zero    m = refl
+-suc (suc n) m = cong suc (+-suc n m)
```

`n = zero`：`zero + suc m` 归约成 `suc m`，右边 `suc (zero + m)` 归约成 `suc m`。`refl`。`n = suc n`：两边各归约一步，剥掉 `suc`，用归纳假设。

有了这个引理，交换律就能写出来：

```agda
+-comm : (a b : ℕ) → a + b ≡ b + a
+-comm zero    b = sym (+-identityʳ b)
+-comm (suc a) b = trans (cong suc (+-comm a b)) (sym (+-suc b a))
```

`a = zero` 时目标变成 `zero + b ≡ b + zero`，左边归约成 `b`，右边是卡住的 `b + zero`。用 `+-identityʳ b` 拿到 `b + zero ≡ b`，再用 `sym` 翻过来。这里不能用 `+-identityˡ`，因为它证的是 `zero + b ≡ b`，方向不对——用 `sym` 就是为了对齐方向。

`a = suc a` 时目标变成 `suc (a + b) ≡ b + suc a`。这一行是两步 `trans`：先用归纳假设把 `suc (a + b)` 变成 `suc (b + a)`，再用 `+-suc b a` 的反向把 `suc (b + a)` 变成 `b + suc a`。你可以把它读成“把右边的 `suc` 从 `b` 前面搬到 `a` 前面”，这正是交换律在做的事。

所以 `+-comm` 的完整依赖是：`+-identityʳ`（处理基础情形）+ `+-suc`（把 `suc` 挪位置）+ 归纳。这三个引理一个都不能少，而 `+-suc` 之所以必须存在，根子上还是因为 `_+_` 只对第一个参数做匹配。

::: tip 读 stdlib 时的一个经验
标准库的 `Algebra` 和 `Data.Nat.Properties` 里有大量这种“为了对齐方向”的引理。它们看起来琐碎，但每一个都对应一条具体的归约障碍。当你不知道需要哪个引理时，试着在纸上把两边各归约一步，看它们卡在哪里——卡住的地方就是你要补的引理。
:::

## `subst`：把性质沿等式搬过去

`subst` 是四条工具里最抽象的一条，用途却很具体：当类型依赖一个值，而那个值被等式替换时，你就需要它。

先看一个场景。定义一个长度写在类型里的向量：

```agda
data Vec (A : Set) : ℕ → Set where
  []  : Vec A zero
  _∷_ : {n : ℕ} → A → Vec A n → Vec A (suc n)

infixr 5 _∷_
```

`Vec A n` 表示“长度为 `n` 的 `A` 列表”。这让类型能区分长度，代价是：一旦长度是变量，替换就变难了。假设你有 `xs : Vec A m` 和一个等式 `p : m ≡ n`，想把 `xs` 当成 `Vec A n` 用——类型检查器不会自动同意，因为 `m` 和 `n` 是两个不同的项。

`subst` 就是干这个的：

```agda
cast : {A : Set} {m n : ℕ} → m ≡ n → Vec A m → Vec A n
cast {A} p xs = subst (Vec A) p xs
```

`subst (Vec A) p xs` 的读法：性质 `P` 取成 `Vec A`（它以 `ℕ` 为索引），等式 `p : m ≡ n` 说明索引可以替换，`xs : P m`，结果是 `P n`。实现只有一行 `subst P refl p = p`：当 `p` 是 `refl` 时，`m` 和 `n` 定义上相同，`P m` 和 `P n` 也是同一个类型，直接返回即可。

顺带解释一下代码里那个 `{A}`：`A` 是隐式参数，默认在子句体里引用不到，只有把它写进左边的模式（`cast {A} p xs`）才能按名字提到它。这也是标准库为什么喜欢用 `module _ {A : Set} where` 把共享参数包一层——包进模块参数之后，块内所有定义都能直接引用 `A`。

同一件事也能直接写，而且更能说明 `refl` 的行为：

```agda
cast′ : {A : Set} {m n : ℕ} → m ≡ n → Vec A m → Vec A n
cast′ refl xs = xs
```

这里的技巧是对 `p` 直接做模式匹配，而不是先拿到 `p` 再替换。匹配成 `refl` 之后，`m` 和 `n` 在上下文里就是同一个变量，`Vec A m` 和 `Vec A n` 也就成了同一个类型，`xs` 直接返回。`cast` 和 `cast′` 是等价的，前者说明“替换是什么”，后者说明“为什么替换能成立”。

这就是 `subst` 的全部内容：它没有增加新知识，只是把“我知道这两个索引相等”变成“类型检查器同意它们是同一个类型”。在依赖类型的证明里，这一步出现的频率高得惊人，以至于标准库专门提供了 `≡-Reasoning` 这样的语法糖，让你把一长串 `trans` 写成：

```text
  a + b
    ≡⟨ 某条引理 ⟩
  b + a
    ∎
```

（这是 `Relation.Binary.PropositionalEquality` 里的 `≡-Reasoning`，需要标准库；本文件不依赖它，所以上面的证明都用了裸的 `trans`。）

::: warning `subst` 的代价
`subst` 看起来只是语法便利，但它引出一个更深的问题：等式替换之后，“原来的值”和“替换后的值”还是同一个东西吗？在简单情形下（比如这里只是改索引）答案是肯定的；在更复杂的类型论里，这正是 **transport** 问题的起点，也是 cubical Agda 想解决的核心困难。本站不展开，但你以后读到 “transport”、“univalence” 这些词时，可以回想起这一行 `subst P refl p = p`。
:::

## 人话总结

<div class="human-note">
<strong>如果只记住一件事：</strong>`refl` 的含义是编译器算出来两边是同一个项，与“我认为它们相等”无关。所以证明等式的全部技巧就是：让未知的部分变成已知的形状。对自然数，这意味着对变量做归纳；对函数，这意味着对齐两边差的那层外壳；对依赖类型，这意味着用 `subst` 把等式搬进类型里。
</div>

## 常见误解

**误解一：`refl` 可以证明任何相等。**

不。`refl` 只在两边定义上相等时可用。`1 + 1 ≡ 2` 可以（归约后都是 `2`），`n + 0 ≡ n` 不行（`n` 未知时归约卡住），`a + b ≡ b + a` 更不行（要归纳 + 引理）。看到 `refl` 报错时不要怀疑人生，去问“它们在定义上差在哪一步归约”。

**误解二：`≡` 就是其他语言里的 `==`。**

完全是两回事。`==` 是一个返回 `Bool` 的函数，运行时才求值，可能返回假；`≡` 是一个类型，它的元素是证明，编译期就被检查。而且 `≡` 不是“比较”，它没有否定形式——你没有 `x ≢ y` 的运行时判断，除非你另外定义一个可判定的相等（decidable equality）。

**误解三：证等式需要数学直觉。**

大部分时候不需要，需要的是耐心。步骤是机械的：看定义在哪归约、把未知变量拆成构造子、对齐差的外壳、该用哪条引理就补哪条。难点在于知道该证哪条辅助引理，而这条引理几乎总是“定义卡住的那个位置”。

**误解四：既然等式证明只有一种，那写哪个证明都一样。**

在默认的 Agda 里，`≡` 的不同证明可以被证明相等（这是 K 公理的一个后果），所以通常不必区分。但这不是普遍规律：打开 `--without-K` 之后，同一等式的不同证明就不再自动相等，等式的结构本身开始携带信息。这也是为什么 cubical 方向的研究者会对“证明怎么写的”格外在意，而对普通工程用途，你可以放心地把证明当成“只要存在就行”。

## 本章小结

- `≡` 是归纳定义的类型，唯一构造子是 `refl : x ≡ x`；它只能证明定义相等的等式。
- `sym`、`trans`、`cong`、`subst` 的实现全都是一行模式匹配，因为它们做的事情就是“把 `refl` 情形认出来”。
- `n + 0 ≡ n` 不能用 `refl`，因为 `_+_` 在第一个参数上递归，`n` 未知时 `n + 0` 卡住不归约。
- 归纳证明就是一个对自己的小一号输入递归调用的函数；`cong` 负责对齐两边差的那层外壳。
- `subst` 把等式从“命题层面”搬进“类型层面”，是依赖类型里做替换的唯一手段。

## 练习

1. 用 `cong` 证明 `(n : ℕ) → suc (n + zero) ≡ suc n`，并说明它和 `+-identityʳ` 的关系：为什么不能直接用 `refl`？
2. 试着把 `+-assoc` 的证明改成对 `c` 归纳而不是对 `a` 归纳。你会卡在哪一步？这个卡住的位置和 `_+_` 的定义顺序有什么关系？
3. 用 `subst` 而不是模式匹配，证明 `cast` 的一个具体实例：给定 `p : m ≡ n` 和 `xs : Vec A m`，构造出 `Vec A n`。然后解释为什么 `subst` 的第一个参数必须是 `Vec A` 而不是 `Vec`。
4. 定义一个可判定的相等 `_≟_ : (m n : ℕ) → (m ≡ n) ⊎ (m ≢ n)` 需要什么？先想清楚 `≢` 该怎么定义（提示：它就是 `¬`），再解释为什么这个问题在 `ℕ` 上可解，而在一般的 `A` 上不可解。
